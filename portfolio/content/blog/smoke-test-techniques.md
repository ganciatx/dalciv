Before you write a single line of code, you need to know if anyone actually wants what you're building. Smoke tests are the fastest way to find out.

## What is a smoke test?

A smoke test is a lightweight experiment designed to measure **demand** before you invest in building a full product. The name comes from electronics — if you plug something in and smoke comes out, you know it's broken before you invest more time.

## Top techniques to try

### 1. Landing page with waitlist

Build a simple landing page describing your product. Drive traffic from your target audience (ads, communities, cold outreach). Measure sign-up rate as a proxy for interest.

**Signal to watch:** Conversion rate above 5% suggests strong interest.

### 2. Concierge MVP

Manually deliver the service your product would automate. If people pay for the manual version, they'll likely pay for the automated one.

**Example:** Before building a meal-planning app, manually create meal plans for 10 customers for a month.

### 3. Fake door test

Add a button or feature to an existing product that doesn't exist yet. Track clicks. If enough people click, build it.

**Caution:** Be transparent if users ask — don't leave them hanging.

### 4. Pre-order campaign

Sell the product before it exists. Platforms like Kickstarter or a simple Stripe checkout page work well.

**Signal to watch:** Actual payment, not just email sign-ups.

### 5. Wizard of Oz

Users think they're interacting with software, but a human is doing the work behind the scenes. Great for testing AI-powered products before building the model.

## Choosing the right test

| Stage | Best test |
|-------|-----------|
| Idea only | Landing page + waitlist |
| Know the problem | Concierge MVP |
| Have existing users | Fake door |
| Ready to commit | Pre-order |

## Next steps

Pick one technique, run it for two weeks, and measure one metric. Don't run five tests at once — you'll learn nothing from the noise.
